# localhost実Turnstile検証（shinseikai-hub-local-test専用）

この環境は公式ダミーキーのブラウザテストと別のCLI・一時アプリです。今回の実装では実キー入力、サーバー起動、Cloudflare通信を実施していません。以下の起動はユーザーの次の実認証承認後に行います。

## 起動

必要なものは、ユーザーが作成したManagedウィジェット`shinseikai-hub-local-test`のlocalhost専用Site Keyと、それと組になるSecret Keyです。キーの内容からウィジェット名・所属を確証できないため、Cloudflare管理画面で組み合わせを確認してください。本番キーを入力しないでください。

プロジェクトのルートで、TTYのあるローカル端末から実行します。

```bash
node scripts/turnstile-local-real/start.mjs --start --allow-siteverify --confirm-local-widget --port 3200
```

各フラグは必須です。入力は両キーとも非表示で、コマンド引数・シェル履歴・設定ファイルへ記載しません。公式ダミーキーの既知パターンは拒否します。非TTYでは起動せず、入力キャンセルはCtrl+Cです。ポート3000・3100は選択できず、使用中ポートのプロセスを終了する処理もありません。

readyが出たら、承認済みのブラウザで`http://localhost:3200/turnstile-check`を開きます。127.0.0.1をURLに使わないでください。ウィジェットを認証し「Siteverifyで検証する」を押すと、1回だけSiteverifyを呼びます。ページ表示自体もCloudflareのスクリプト・チャレンジ通信を伴います。

## 構成と分離

- 既存の`.env.local`や他の.envファイルを読み込まず、コピーもしません。
- 一時Next.jsアプリはOSの一時領域に生成し、コピー元は専用テンプレート、既存ウィジェット、変更なしの`lib/security/turnstile.ts`だけです。node_modulesはシンボリックリンクで再利用します。
- 子環境は許可したOS変数と今回入力したキーだけ。既存のTurnstile・Supabase・Redis・NODE_OPTIONSなどは継承しません。
- hostnameは`localhost`、actionは`registration`固定。照合・5秒タイムアウト・失敗時拒否は既存関数のままです。
- 新規アプリは`next dev --webpack --hostname 127.0.0.1`で直接起動し、Next自身が開発用WebSocketを処理します。既存プロキシや3100番の挙動は変更しません。診断の出力分類だけを既存コードから再利用します。
- Site KeyをNEXT_PUBLIC環境変数でビルドに埋め込まず、`GET /local-test/site-key`からブラウザのメモリへ渡します。公開Site KeyはブラウザのNetwork等から閲覧できます。Secret Keyはサーバー環境にだけ保持し、ページ・API応答・生成ファイルへ書き込みません。
- 一時アプリに実申込API・Supabase・Redisコードや接続設定はありません。`/api/registrations`、管理API、未定義経路は404で遮断します。

## ガードと上限

- Hostは`localhost:<起動ポート>`、専用POSTのOriginは`http://localhost:<起動ポート>`と完全一致。
- APIは`POST /api/turnstile-check`のみ。JSONは`token`1項目だけ、本文4KiB、読み込み3秒、トークン1〜2048のASCII文字。
- 検証中の二重操作は拒否。送信済みトークンはSHA-256識別子だけをメモリに保持し、成功・拒否・結果不明いずれでも再送しません。自動再試行はありません。
- Siteverifyは検証プロセスあたり最大3回。失敗・タイムアウトも消費します。NextのホットリロードではglobalThis上のガードを再利用しますが、サーバープロセス自体の再起動では上限がリセットされます。上限を回避する再起動はしないでください。
- 結果は`VERIFIED`か固定の安全なコードだけで、申込完了とは表示しません。すべての専用応答はno-store。トークン・Secret・上流本文・例外原文はログに出しません。
- 起動自己診断は`GET /local-test/status`だけで、Siteverifyは呼びません。

## 実認証での確認と後片付け

正常系では新しい認証を取得して、5分以内に検証します。通信結果不明時は自動再送せず、結果を確認してから別の認証を取得してください。ウィジェットは毎回作り直し、ブラウザの永続ストレージへトークンは保存しません。フォームに参加者の個人情報を入力する欄はありません。

本環境は重複トークンをCloudflare到達前に拒否するため、Cloudflare自身の再使用判定の実測は対象外です。必要なら別の承認・設計で実施してください。

終了はCtrl+Cです。今回生成した子プロセスを終了してから一時ディレクトリを削除します。終了に失敗した場合はファイル削除を止め、安全な失敗分類を出します。強制終了・OS停止では一時ファイルが残る可能性がありますが、入力キーをそれらの設定ファイルへ保存する設計ではありません。

専用キーをチャット・画面共有・HAR・スクリーンショットへ含めないでください。環境変数は同一OSユーザー・管理者のプロセス調査から完全に秘匿できるものではありません。信頼できるローカル端末でだけ実行してください。

## 自動テスト（実通信なし）

```bash
node --test tests/turnstile-local-real.test.mjs
```

既存検証関数をVM内でモックfetchと接続し、hostname/action・障害・タイムアウトを検証します。ガード、非表示入力、子環境、禁止API、後片付け、キーを含まない一時アプリの生成・型検査も確認します。キー入力テストは合成文字列・疑似TTYで、実キーは扱いません。サーバー・ソケット・ブラウザは起動しません。

実Next起動、実端末での非表示入力、実ウィジェット・Siteverify、終了後の実ポート解放は未確認です。

## 起動診断と終了の判定

ヘルス確認とSite Key取得は、App Routerの通常フォルダ`app/local-test/`を使用します。`app/__test/`は非公開フォルダ扱いになるため使用しません。Nextの実ルート判定を架空・一時パスで呼び出す回帰テストで、両ルートが登録されることを確認します（サーバー起動なし）。

ヘルス確認は`GET /local-test/status`だけです。HTTPステータスは`http_status`に記録し、404・500・不正JSON・本文サイズ超過では`HTTP_ERROR`として直ちに停止します。接続待機の上限到達は`STARTUP_TIMEOUT`で、許可した通信コードだけを保持します。応答本文・例外原文は出力しません。

起動失敗・Ctrl+C等による後片付けは、子プロセスへの終了要求より先に「予定した終了」として扱います。その後の終了コード0を`CHILD_EARLY_EXIT`として二重報告しません。予定していない子プロセス終了はコード0の場合も引き続き検出します。
